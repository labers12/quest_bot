# Quest Bot

Telegram-бот с текстовым квестом, разветвлённым сюжетом и системой инвентаря.

Игрок проходит квест, выбирает действия с помощью кнопок, исследует локации, получает предметы и использует их для открытия новых вариантов прохождения.

Проект написан на Python с использованием **aiogram 3**. Сюжет и игровая логика отделены от кода бота и хранятся в JSON.

## Возможности

- Текстовый квест с разветвлённым сюжетом
- Интерактивные кнопки Telegram
- Переходы между сценами
- Система предметов и инвентаря
- Предметы, необходимые для выполнения определённых действий
- Победные и проигрышные состояния
- Сохранение состояния игрока в SQLite
- Автоматический сброс прогресса после завершения квеста
- Отдельное хранение данных квеста и логики бота
- Поддержка русской и английской версий квеста

## Как устроен квест

Квест состоит из отдельных **сцен**.

Каждая сцена содержит:

- описание происходящего;
- доступные действия;
- переходы на другие сцены;
- предметы, которые можно получить;
- предметы, необходимые для выполнения действия;
- признак победы или проигрыша.

Упрощённо структура выглядит так:

```text
Сцена
├── описание
├── предметы
└── действия
    ├── действие → другая сцена
    ├── действие → другая сцена
    └── действие → другая сцена
```

Например, действие может требовать определённый предмет:

```json
{
    "target": "open_door",
    "text": "Открыть дверь",
    "required_items": ["key"]
}
```

Если у игрока нет `key`, действие недоступно.

Благодаря этому сюжет можно изменять и расширять без необходимости прописывать каждую сцену непосредственно в Python-коде.

## Установка

### 1. Клонировать репозиторий

```bash
git clone https://github.com/labers12/quest_bot.git
cd quest_bot
```

### 2. Создать виртуальное окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Для Windows:

```powershell
.venv\Scripts\activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Создать Telegram-бота

Создайте бота через **@BotFather** и получите его токен.

В корне проекта создайте файл `.env`:

```env
TOKEN=your_telegram_bot_token
```

Токен нельзя публиковать в репозитории.

### 5. Запустить бота

```bash
python -m src.bot
```

После запуска бот начнёт получать обновления от Telegram.

## Команды

### `/start`

Запускает квест и начинает новое прохождение.

### `/inventory`

Показывает предметы, которые игрок получил во время прохождения.

## Изменение квеста

Основные данные квеста находятся в:

```text
data/quest_data.json
```

Сцены можно связывать между собой через действия.

Например:

```text
                ┌──────────────┐
                │    Сцена A   │
                └──────┬───────┘
                       │
              ┌────────┴────────┐
              ▼                 ▼
        ┌──────────┐      ┌──────────┐
        │  Сцена B │      │  Сцена C │
        └──────────┘      └──────────┘
```

Это позволяет создавать разные варианты развития сюжета.

Предметы могут добавляться в инвентарь игрока:

```json
"items_to_add": [
    {
        "id": "key",
        "name": "Ключ"
    }
]
```

А затем использоваться как условие для другого действия:

```json
"required_items": ["key"]
```

Таким образом можно реализовывать простые головоломки и последовательности действий.

## Хранение состояния

Состояние игроков хранится в SQLite.

Для каждого игрока сохраняется необходимая информация о текущем прохождении, включая:

- текущую сцену;
- полученные предметы;
- прогресс квеста.

Это позволяет боту сохранять состояние между сообщениями и перезапусками.

## Архитектура

Проект разделён на несколько основных частей:

```text
                 Telegram
                     │
                     ▼
              ┌─────────────┐
              │   aiogram   │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │  Handlers   │
              └──────┬──────┘
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
   ┌─────────────┐       ┌─────────────┐
   │ Quest data  │       │   SQLite    │
   │    JSON     │       │  Database   │
   └─────────────┘       └─────────────┘
```

**JSON** отвечает за содержание квеста.

**Handlers** отвечают за взаимодействие пользователя с ботом.

**SQLite** хранит состояние прохождения.

Такое разделение позволяет менять сюжет, не переписывая основную логику Telegram-бота.
